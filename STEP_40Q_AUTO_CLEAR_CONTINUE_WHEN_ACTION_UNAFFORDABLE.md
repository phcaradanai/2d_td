# STEP_40Q_AUTO_CLEAR_CONTINUE_WHEN_ACTION_UNAFFORDABLE.md

## 1. Why Auto Clear Failed After Wave 1
Auto Clear failed because it tried to execute a planned `place_tower` action for a `cannon_tower` (cost: 110) but the current gold was only 83. The previous implementation treated all action failures as fatal, calling `_fail()`, which terminated the run.

## 2. Why cannon_tower was selected despite insufficient gold
The plan (generated by the Solver) expected enough gold to be available, but gameplay variance or mid-wave decisions might have depleted resources. The verifier was too rigid in following the plan's builds without checking affordability or allowing for skips.

## 3. Why reset_waves was called before Wave 2
The `_fail()` function automatically calls `wave_manager.reset_waves()` to clean up the level. Since the unaffordable action triggered `_fail()`, the wave manager was reset, causing `current_wave_index` to drop to 0, which broke the continuation to Wave 2.

## 4. What should happen when a planned action is unaffordable
If an optional action (like a build or upgrade between waves) is unaffordable:
1. It should be marked as **SKIPPED**.
2. Auto Clear should attempt to find a **CHEAPER FALLBACK** (e.g., placing a Basic Tower instead of a Cannon Tower).
3. If no fallback is affordable, it should simply continue to the next action or start the next wave.
4. The run should ONLY fail if a **REQUIRED** action (like starting the wave or initial setup) fails or if HP is lost.

## 5. Final Next-Wave Continuation Rules
- **No Resets**: `reset_waves()` is blocked during the transition phase.
- **HP Priority**: As long as HP is full, the system will attempt to proceed even if some builds were skipped.
- **Automatic Continuation**: The next wave will always be started automatically after optional actions are processed.
